# backend

## 목적
- 이 스킬은 API, 서비스 로직, 데이터 접근, 도메인 흐름 정리에 사용한다.
- 요청 처리 흐름을 계층별 책임에 맞게 나누도록 돕는다.
- 구현 속도보다 예측 가능한 구조와 변경 용이성을 우선하도록 유도한다.

## 언제 사용하나
- API 엔드포인트를 추가하거나 수정할 때
- 서비스 레이어, 저장소 레이어, 데이터 흐름을 정리할 때
- 유효성 검사, 에러 처리, 비즈니스 규칙을 구현할 때

## 작업 원칙
- 현재 작업의 범위와 완료 기준은 `tasks/current.md`를 따른다.
- 요청 진입점, 비즈니스 로직, 데이터 접근 책임을 분리한다.
- 입력 검증은 경계에서 빠르게 수행한다.
- 비즈니스 규칙은 서비스 레이어에 둔다.
- 데이터 접근은 전용 레이어나 일관된 접근 방식으로 통일한다.
- 에러는 호출자가 이해할 수 있는 형태로 일관되게 반환한다.

## 우선 확인할 것
1. `tasks/current.md`
2. `.ai/map.md`
3. `.ai/memory/patterns.md`
4. 관련 API, 서비스, 저장소 파일

## 하지 말 것
- 컨트롤러나 핸들러에 비즈니스 로직을 과도하게 넣지 않는다.
- 여러 계층에서 같은 검증 로직을 중복 작성하지 않는다.
- 데이터 접근 코드를 이곳저곳에 흩뿌리지 않는다.
- 에러 처리 방식을 엔드포인트마다 다르게 만들지 않는다.

## 요청 예시
```text
tasks/current.md 기준으로 백엔드 기능 구현해줘.
레이어 책임이 섞이지 않게 정리해줘.
```

```text
이 API 흐름에서 검증, 서비스 로직, 데이터 접근을 분리해서 리팩토링해줘.
```
