# review

## 목적
- 이 스킬은 코드 리뷰, 변경 검토, 회귀 위험 점검에 사용한다.
- 칭찬보다 문제 발견과 위험 식별을 우선하도록 돕는다.
- 리뷰 결과가 바로 수정 요청으로 이어질 수 있게 구체성을 높인다.

## 언제 사용하나
- 작업 완료 후 코드 리뷰를 요청할 때
- PR 전 자체 점검이 필요할 때
- 리팩토링이나 구조 변경의 위험을 확인할 때

## 작업 원칙
- 리뷰 기준은 먼저 `tasks/current.md`의 목표와 완료 기준에 맞춰 본다.
- 변경 요약보다 버그, 회귀, 누락된 테스트, 구조 위반을 먼저 본다.
- 지적은 반드시 파일과 근거 중심으로 정리한다.
- 추측과 확인된 사실을 구분한다.
- 발견 사항이 없으면 그 사실과 남은 리스크를 함께 적는다.

## 우선 확인할 것
1. `tasks/current.md`
2. `.ai/rules.md`
3. `.ai/memory/patterns.md`
4. 변경된 코드와 관련 테스트

## 하지 말 것
- 코드 스타일 취향만으로 과도한 수정을 요구하지 않는다.
- 근거 없이 "문제 없어 보인다"로 끝내지 않는다.
- 요약만 길고 실제 발견 사항이 없는 리뷰를 하지 않는다.
- 테스트 누락이나 예외 케이스를 그냥 넘기지 않는다.

## 요청 예시
```text
tasks/current.md 완료 기준으로 코드 리뷰해줘.
버그, 회귀 위험, 테스트 누락 위주로 봐줘.
```

```text
이 변경사항을 리뷰하고 우선순위 높은 문제부터 정리해줘.
```
