# frontend

## 목적
- 이 스킬은 UI, 페이지, 컴포넌트, 폼, 상태 연결 같은 프론트엔드 작업에 사용한다.
- 화면 구현과 로직 분리를 함께 고려하도록 돕는다.
- 빠른 구현보다 구조 일관성과 유지보수성을 우선하도록 유도한다.

## 언제 사용하나
- 새 페이지나 컴포넌트를 만들 때
- 폼 검증, 사용자 입력 처리, 화면 상태 관리를 다룰 때
- 기존 UI를 리팩토링하거나 공통 컴포넌트로 분리할 때

## 작업 원칙
- 현재 작업의 목표와 완료 기준은 항상 `tasks/current.md`를 따른다.
- `src/` 구조는 `.ai/map.md`에 맞춘다.
- UI와 비즈니스 로직은 가능한 분리한다.
- API 호출은 직접 하지 말고 프로젝트의 서비스 레이어를 경유한다.
- 재사용 가능한 UI는 공통 컴포넌트로 분리한다.
- 상태는 범위에 맞게 로컬 상태, 서버 상태, 전역 상태를 나눈다.

## 우선 확인할 것
1. `tasks/current.md`
2. `.ai/map.md`
3. `.ai/memory/patterns.md`
4. 관련 화면 또는 컴포넌트 파일

## 하지 말 것
- 페이지 컴포넌트에 과도한 비즈니스 로직을 직접 넣지 않는다.
- 같은 UI 패턴을 복붙으로 반복하지 않는다.
- 검증 로직, 데이터 변환, API 호출을 한 파일에 몰아넣지 않는다.
- 공통 규칙 없이 임의의 폴더 구조를 만들지 않는다.

## 요청 예시
```text
tasks/current.md 기준으로 프론트엔드 구현해줘.
기존 src 구조와 패턴을 최대한 유지해줘.
```

```text
이 폼 화면을 구현하되 검증 로직과 UI를 분리해서 정리해줘.
```
